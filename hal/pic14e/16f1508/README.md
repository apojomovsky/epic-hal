# PIC16F1508 / PIC16F1509 HAL

Register-level HAL for the PIC16F1508 and PIC16F1509 (Enhanced
Mid-range core). This first PR onboards the part with the minimum
peripheral set needed to prove the family end to end: the family header
and SFR map, GPIO (PORTA, PORTB, PORTC), and the interrupt-on-change
(IOC) interrupt source.

Register facts come from the pinned Microchip DFP 1.9.258 EDC
(`PIC16F1509.PIC`), not from a datasheet page. Datasheet section cites
are pending a human-supplied copy of the datasheet, so `MANUAL.md`
marks what is unverified.

The family follows the same shared contract as the other HALs
(`common/README.md`, `common/MANUAL.md`). Names and signatures match
`hal/pic14e/16f193x/`, with the register bodies specific to this part.
The procedure for adding a family is in
[docs/adding-a-device.md](../../../docs/adding-a-device.md).

## Status

Implemented and verified:

- [x] Family SFR map (`include/pic16f1508_sfr.h`), generated by
      `scripts/build/gen-sfr.py` from the pinned EDC
- [x] Implemented-pin masks per port (`include/pic16f1508.h`)
- [x] GPIO on PORTA, PORTB, PORTC: init, read/write pin and port,
      toggle, pull-ups, analog select, interrupt-on-change enable
- [x] Interrupt core for IOC and CLC1..CLC4 (`INTCON.IOCIE`, and
      `PIR3`/`PIE3` for CLC; gated dispatch, single vector, automatic
      hardware context save)
- [x] Host simulation backend and `example_gpio` probe (ctest).
- [x] Real-target firmware (`epic-pic16f1508-firmware`), `blink` example,
      and the mdb register-readback gate (`MODE=gpio`, RA0 PASS marker) for
      GPIO, IOC enable, and CLC output behaviour (modes 0..3, 5 and 6
      through gate-polarity constants, CON.OUT readback; the SIM gaps that
      shape it are in MANUAL.md, #383).

Implemented and verified against DS40001609E: the `EPIC_CLC` driver (mode,
source codes from `EPIC_CLC_SourceCode`, per-cell INTP/INTN edge select,
CLC1..CLC4 interrupt routing with an optional per-cell callback; host probes
`example_clc`, `example_clc_src` and `example_clc_irq`) and the host-sim CLC
model (gate and mode logic with sequential state, CLCDATA and CON.OUT
mirrors, INTN/INTP edge flags; Dx levels come from a host-only hook, probe
`example_clc_sim`). Register bits, the Table 24-1 input-select codes and the
Figure 24-3 gate roles are checked against the datasheet (see MANUAL.md).
The S-R latch demo (TB3273 shape: S on D1+D2, R on D3+D4, mode 3) is probe
`example_clc_latch` on the host and a set/hold/reset/hold-low section of the
mdb gate on target. The beat-frequency sweep on top of it is probe
`example_clc_beat`: S and R trains at the MCC 256:255 period ratio sweep the
duty from near-empty to near-full at a fixed output rate with no register
written after setup. The on-silicon S and R trains come from TMR2 (PR2 255)
and a TMR1 preloaded to 0xFF01 (see the timer drivers below).
The switch-debouncer demo (AN2805 2-CLC shape: STAGE1 samples the switch on
the slow clock, STAGE2 samples switch AND STAGE1, both mode 5) is probe
`example_clc_debounce` on the host and D-flop plus filter-gate sections of
the mdb gate on target; the slow clock is the `EPIC_TIMER2` free-run below.
The quadrature-decoder-assist demo (two mode-6 J-K cells, each
clocking on one encoder line while the other sets it, with a software
counter and a 10-LED bar on RC0..RC7, RA4, RA5) is probe `example_clc_quad`
on the host and a J-K section of the mdb gate on target; the counter path
is the `EPIC_TIMER1` T1CKI counter below (no TMR3 on this part).

Implemented and verified against DS40001609E: the `EPIC_TIMER2` driver
(prescalers 1:1/1:4/1:16/1:64, postscaler 1:1..1:16, PR2 match with TMR2IF
and an optional match callback; host probe `example_tmr2`) and the
`EPIC_TIMER1` driver (16-bit timer/counter: internal FOSC/4 plus external
T1CKI counter mode for the quadrature assist, prescalers 1:1/1:2/1:4/1:8,
overflow flag with an optional callback; host probe `example_tmr1`). TMR2IF
and TMR1IF route through the shared dispatcher with PEIE gating, and the
host sim advances both timers per instruction tick with prescalers, PR2
match and postscaler modelled. T2_match reaches CLC Dx at D1 code 7 and D2
code 3, T1_overflow at D1 code 6 and D2 code 2 (Table 24-1): TMR2 is the
debouncer slow clock, and a TMR1 preloaded to 0xFF01 overflowing every 255
counts against TMR2 at PR2 255 matching every 256 is the on-silicon 256:255
beat pair (proven in `example_tmr1`). The part has no TMR3, TMR4 or TMR6,
so the ticket's TMR1/TMR3 pair is TMR1-only here. The mdb gate covers both
timers (match/overflow flag within a bounded spin, then the POR state).

Not yet implemented (deliberate scope limit, each its own follow-up):

- Timer0, CCP, ADC, EEPROM, EUSART, MSSP, WDT and sleep helpers,
  comparators, DAC, FVR, NCO, CWG, and the SR latch.
- Wiring the landed timer drivers into the demos (the debouncer TMR2 clock,
  the quadrature TMR1 counter, the on-silicon TB3273 auto-dimmer) and the
  CLC sequential modes on the mdb gate (modes 3, 5 and 6 run in the gate;
  modes 4 and 7 and cross-cell cascades run host-only; MPLAB-SIM shapes
  the gate, see MANUAL.md, #383). The sweep itself is probe
  `example_clc_beat` on the host.
- SEL-code decoding in the host sim (codes are stored, Dx levels come from a
  host-only hook, except timer overflow/match which the tick model raises).
- A 16F188xx part. It is not in the pinned DFP.

## Quick start

Host simulation (no hardware, no toolchain):

```sh
cmake -B build && cmake --build build && ctest --test-dir build
./build/example_gpio
```

Real target (needs XC8 and the PIC12-16F1xxx DFP):

```sh
python3 scripts/build/epic_build.py build --module epic-pic16f1508-firmware --mcu 16F1509 --run
```

Docker: `make test MODULE=hal/pic14e/16f1508`,
`make xc8-build MODULE=epic-pic16f1508-firmware MCU=16F1509`,
`make mdb-test MODULE=epic-pic16f1508-firmware MCU=16F1509 DEVICE=PIC16F1509 WAIT_MS=60000 MODE=gpio`.

```
include/
  pic16f1508.h          device masks and capability macros
  pic16f1508_sfr.h      SFR addresses (generated), bit masks
  host/                 host platform header (memory-backed SFR array)
  target/               target platform header (volatile-deref SFR)
  core/                 IRQ contract
  peripherals/          GPIO, CLC, Timer1, Timer2 contracts
src/
  core/                 IRQ backend and dispatch
  peripherals/          GPIO, CLC, Timer1 and Timer2 bodies
  target/               ISR vector (real hardware only)
  sim/                  host simulation backend
  mdb/                  MPLAB SIM register-readback harness
tests/                  example_blink, example_gpio (host), example_clc (host),
                        example_clc_irq (host), example_clc_sim (host),
                        example_clc_latch (host), example_clc_beat (host),
                        example_clc_debounce (host), example_clc_quad (host),
                        example_tmr1, example_tmr2 (host),
                        example_gpio_mdb
```

## Implemented pins

Only the pins the EDC implements are driven. Writes to unimplemented
bits are dropped by hardware, and the driver masks them so the intent
is explicit.

| Port  | Implemented     | Note                                                              |
|-------|-----------------|-------------------------------------------------------------------|
| PORTA | 0x3F (RA0..RA5) | LATA is 0x37: LATA3 unimplemented, RA3 input-only (MCLR)          |
| PORTB | 0xF0 (RB4..RB7) | RB0..RB3 do not exist on this part                                |
| PORTC | 0xFF (RC0..RC7) | Width from EDC; not checked against a datasheet                   |

Interrupt-on-change covers RB4..RB7 only (`IOCBP`, `IOCBN`, `IOCBF`).
PORTA and PORTC have no IOC in this HAL.

## Known limits

- The host simulation does not model unimplemented bits. The host probe
  and the mdb probe therefore use the implemented masks, and the LATA
  check compares only implemented bits. A host pass does not prove the
  driver masks correctly. The mdb gate is the proof for those bits.
- The IOC handler calls the registered callback only when one is set. In
  the blink build XC8 advisory 2098 and warning 759 report the callback
  call as ignored. [INFERENCE] The only writer of the callback pointer,
  `EPIC_GPIO_RegisterChangeCallback`, is not referenced in that link, so
  the pointer is known NULL. The host probe (`tests/example_gpio.c`)
  registers a callback, the mdb probe does not. The cross-unit
  registration path is not exercised by a target build.
