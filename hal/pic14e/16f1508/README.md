# PIC16F1508 / PIC16F1509 HAL

Register-level HAL for the PIC16F1508 and PIC16F1509 (Enhanced
Mid-range core). This first PR onboards the part with the minimum
peripheral set needed to prove the family end to end: the family header
and SFR map, GPIO (PORTA, PORTB, PORTC), and the interrupt-on-change
(IOC) interrupt source.

Register facts come from the pinned Microchip DFP 1.9.258 EDC
(`PIC16F1509.PIC`), not from a datasheet page. Datasheet section cites
are pending a human-supplied copy of the datasheet, so `MANUAL.md`
marks what is unverified.

The family follows the same shared contract as the other HALs
(`common/README.md`, `common/MANUAL.md`). Names and signatures match
`hal/pic14e/16f193x/`, with the register bodies specific to this part.
The procedure for adding a family is in
[docs/adding-a-device.md](../../../docs/adding-a-device.md).

## Status

Implemented and verified:

- [x] Family SFR map (`include/pic16f1508_sfr.h`), generated by
      `scripts/gen-sfr.py` from the pinned EDC
- [x] Implemented-pin masks per port (`include/pic16f1508.h`)
- [x] GPIO on PORTA, PORTB, PORTC: init, read/write pin and port,
      toggle, pull-ups, analog select, interrupt-on-change enable
- [x] Interrupt core for IOC only (`INTCON.IOCIE` gated dispatch, single
      vector, automatic hardware context save)
- [x] Host simulation backend and `example_gpio` probe (ctest)
- [x] Real-target firmware (`epic-pic16f1508-firmware`), `blink` example,
      and the mdb GPIO register-readback gate (`MODE=gpio`, RA0 PASS
      marker)

Not yet implemented (deliberate scope limit, each its own follow-up):

- Timers, CCP, ADC, EEPROM, EUSART, MSSP, WDT and sleep helpers,
  comparators, DAC, FVR, and the SR latch.
- The CLC driver (`EPIC_CLC`). The CLC cell count is in the EDC (four
  cells), but the CLC register bits and input-select table are not
  verified against the datasheet yet.
- A 16F188xx part. It is not in the pinned DFP.

## Quick start

Host simulation (no hardware, no toolchain):

```sh
cmake -B build && cmake --build build && ctest --test-dir build
./build/example_gpio
```

Real target (needs XC8 and the PIC12-16F1xxx DFP):

```sh
python3 scripts/epic_build.py build --module epic-pic16f1508-firmware --mcu 16F1509 --run
```

Docker: `make test MODULE=hal/pic14e/16f1508`,
`make xc8-build MODULE=epic-pic16f1508-firmware MCU=16F1509`,
`make mdb-test MODULE=epic-pic16f1508-firmware MCU=16F1509 DEVICE=PIC16F1509 WAIT_MS=60000 MODE=gpio`.

## Layout

```
include/
  pic16f1508.h          device masks and capability macros
  pic16f1508_sfr.h      SFR addresses (generated), bit masks
  host/                 host platform header (memory-backed SFR array)
  target/               target platform header (volatile-deref SFR)
  core/                 IRQ contract
  peripherals/          GPIO contract
src/
  core/                 IRQ backend and IOC dispatch
  peripherals/          GPIO body
  target/               ISR vector (real hardware only)
  sim/                  host simulation backend
  mdb/                  MPLAB SIM register-readback harness
tests/                  example_blink, example_gpio (host), example_gpio_mdb
```

## Implemented pins

Only the pins the EDC implements are driven. Writes to unimplemented
bits are dropped by hardware, and the driver masks them so the intent
is explicit.

| Port  | Implemented     | Note                                                              |
|-------|-----------------|-------------------------------------------------------------------|
| PORTA | 0x3F (RA0..RA5) | LATA is 0x37: LATA3 unimplemented, RA3 input-only (MCLR)          |
| PORTB | 0xF0 (RB4..RB7) | RB0..RB3 do not exist on this part                                |
| PORTC | 0xFF (RC0..RC7) | Width from EDC; not checked against a datasheet                   |

Interrupt-on-change covers RB4..RB7 only (`IOCBP`, `IOCBN`, `IOCBF`).
PORTA and PORTC have no IOC in this HAL.

## Known limits

- The host simulation does not model unimplemented bits. The host probe
  and the mdb probe therefore use the implemented masks, and the LATA
  check compares only implemented bits. A host pass does not prove the
  driver masks correctly. The mdb gate is the proof for those bits.
- The IOC handler calls the registered callback only when one is set. In
  the blink build XC8 advisory 2098 and warning 759 report the callback
  call as ignored. [INFERENCE] The only writer of the callback pointer,
  `EPIC_GPIO_RegisterChangeCallback`, is not referenced in that link, so
  the pointer is known NULL. The host probe (`tests/example_gpio.c`)
  registers a callback, the mdb probe does not. The cross-unit
  registration path is not exercised by a target build.
