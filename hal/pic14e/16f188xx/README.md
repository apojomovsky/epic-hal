# PIC16F188xx HAL

Register-level HAL for the PIC16F188xx family (Enhanced Mid-range
core): 16F18854/55/56/57 (28-pin) and 16F18875/76/77 (40-pin, adding
PORTD and PORTE). This HAL covers the family header and SFR map, GPIO
(PORTA..PORTC, plus PORTD/PORTE on the 40-pin parts), and the
interrupt-on-change (IOC) interrupt source with the shared dispatcher
behind the single vector.

Register facts come from the pinned Microchip.PIC16F1xxxx_DFP 1.32.471
EDC (`PIC16F18855.PIC`) and its proc header, not from a datasheet page.
The DS40001802 PDF is bot-walled against scripted fetch, so `MANUAL.md`
marks every fact DFP-derived until a human-supplied copy lets pages be
checked.
The family follows the same shared contract as the other HALs
(`common/README.md`, `common/MANUAL.md`). Names and signatures match
`hal/pic14e/16f1508/`, except `EPIC_GPIO_EnableChangeDetect` takes a
leading port (every pin of PORTA..PORTC is IOC-capable here; PORTD has
no IOC registers and PORTE IOC is RE3 only, so neither arms edges),
with the register bodies specific to this family.
The procedure for adding a family is in
[docs/adding-a-device.md](../../../docs/adding-a-device.md).

## Status

Implemented and verified:

- [x] Family SFR map (`include/pic16f188xx_sfr.h`), generated by
      `scripts/build/gen-sfr.py` from the pinned EDC
- [x] Implemented-pin masks per port (`include/pic16f188xx.h`)
- [x] GPIO on PORTA..PORTC (all parts) and PORTD/PORTE (40-pin parts):
      init, read/write pin and port, toggle, pull-ups, analog select,
      per-port interrupt-on-change enable
- [x] Interrupt core for IOC (`PIE0`/`PIR0` bit 4, PEIE-gated
      dispatch, single vector, automatic hardware context save)
- [x] Host simulation backend and `example_gpio` probe (ctest).
- [x] Real-target firmware (`hal/pic14e/16f188xx`), `blink` example,
      and the mdb register-readback gate (`MODE=gpio`, RA0 PASS marker)
      for GPIO and the IOC enable path. The gate's live vector section
      runs where a software flag write reads back (host sim, real
      silicon); MPLAB SIM ignores it, so there it covers readbacks
      only (family MANUAL.md).
Not yet implemented (deliberate scope limit, each its own follow-up):
- Timer0/1/2, CCP/PWM, ADC, EEPROM, EUSART, MSSP, WDT and sleep helpers,
  comparators, DAC, FVR, NCO, PPS setup, and the remaining peripherals.
- Wiring the family into the demos.

## Quick start

Host simulation (no hardware, no toolchain):

```sh
cmake -B build && cmake --build build && ctest --test-dir build
./build/example_gpio
```

Real target (needs XC8 and the PIC16F1xxxx DFP):

```sh
python3 scripts/build/epic_build.py build --module hal/pic14e/16f188xx --mcu 16F18877 --run
```

Docker: `make test MODULE=hal/pic14e/16f188xx`,
`make xc8-build MODULE=hal/pic14e/16f188xx MCU=16F18877`,
`make mdb-test MODULE=hal/pic14e/16f188xx MCU=16F18877 DEVICE=PIC16F18877 WAIT_MS=60000 MODE=gpio`.

```
include/
  pic16f188xx.h       device masks and capability macros
  pic16f188xx_sfr.h   SFR addresses (generated), bit masks
  host/               host platform header (memory-backed SFR array)
  target/             target platform header (volatile-deref SFR)
  core/               IRQ contract
  peripherals/        GPIO contract
src/
  core/               IRQ backend and dispatch
  peripherals/        GPIO body
  target/             ISR vector (real hardware only)
  sim/                host simulation backend
  mdb/                MPLAB SIM register-readback harness
tests/                example_blink, example_gpio (host),
                      example_gpio_mdb
```

## Implemented pins

All of PORTA..PORTC is implemented on every part (every
PORTx/TRISx/LATx/WPUx/ANSELx/IOCx register reports impl 0xFF in the
EDC, except the PORTC read register at impl 0xC0; all eight RC fields
are defined and TRISC/LATC report 0xFF, so the 0xFF mask stands).
RA6/RA7 are digital I/O under the manifest config (FEXTOSC=OFF).

| PORTA | 0xFF (RA0..RA7) | RA6/RA7 need FEXTOSC=OFF for digital use    |
| PORTB | 0xFF (RB0..RB7) |                                             |
| PORTC | 0xFF (RC0..RC7) |                                             |
| PORTD | 0xFF (RD0..RD7) | 40-pin parts only                           |
| PORTE | 0x07 (RE0..RE2) | 40-pin parts only; RE3 is input-only (MCLR) |

Interrupt-on-change covers every pin of PORTA..PORTC (`IOCxP`,
`IOCxN`, `IOCxF` per port, shared `PIR0.IOCIF`). PORTD has no IOC
registers; PORTE IOC is RE3 only, which has no driver.

## Known limits

- The host simulation does not gate pin reads on ANSEL: an analog pin
  still reads its driven level. The driver sets ANSEL correctly, and
  the mdb gate is the proof those writes land.
- The IOC handler calls the registered callback only when one is set.
