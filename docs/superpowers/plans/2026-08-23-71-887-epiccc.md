# 71 - PIC16F887 epic-cc HAL variant (blinky smoke)

**Ticket:** `epic-hal#71` - Build `pic16f88x-hal` for 16F887 through epic-cc
**Parent:** `epic-hal#58` (HAL-2 backend), `epic-hal#70` (registry, closed), `epic-cc#85` (p16f887 device, closed), `pic16f87xa_gpio_epiccc.c` exemplar
**Scope:** HAL-side only. No compiler work, no generated SFR header (handled by #70).

## Goal

Prove the epic-cc toolchain on a second PIC14 part: `pic16f88x-hal` + `blinky` for `16F887` via `epic_build.py --toolchain epic-cc` (`epic-cc --target 16F887`). Smoke in `crates/sim` or a single `mdb` register read per `docs/adding-a-device.md` §4. File any epic-cc gap instead of silently working around.

## What already exists

- `pic16f88x-hal` family (882/883/884/886/887) with `pic16f88x.h` defaulting to `PIC16F887`, `pic16f88x_sfr.h` and `variants` entry.
- `include/epiccc/pic16f88x_platform.h`, `src/epiccc/pic16f88x_wdt_sleep_epiccc.c`, `src/epiccc/pic16_isr_vector.c` (HAL-1). Same shape as `pic16f87xa-hal` equivalents.
- `scripts/epic_build.py` toolchain=`epic-cc` path: `--target <mcu>` forwarding, `EPIC_CONFIG` TU, `epic-cc.h` include, `__EPIC_CC__` define, and `_epiccc_source`/`_epiccc_include` mapping (merged in #73/#75).
- `pic16f87xa-hal/src/epiccc/pic16f87xa_gpio_epiccc.c` exemplar: literal SFR addresses via `if-else` / `switch-case` per port, avoiding runtime `inttoptr` and LLVM `switch` lowering that `irparse` rejects.

Missing: the 88X GPIO epic-cc variant. `scripts/epic_build.py:_epiccc_source` currently returns the in-place `pic16f88x_gpio.c` unchanged with comment "No separate epiccc file yet". That file uses `tris_addr(port)` / `port_addr(port)` → `EPIC_REG8(variable)` and `switch` on `GPIO_TypeDef`, which lowers to variable `inttoptr` and is rejected by `irparse` (same failure that motivated the 87XA file).

## Design

### 1. `pic16f88x-hal/src/epiccc/pic16f88x_gpio_epiccc.c` (new)

Sibling to `src/peripherals/pic16f88x_gpio.c`, mirrored from `pic16f87xa_gpio_epiccc.c` with 88X differences:

- **Literal addresses only.** Each API (`Init`, `DeInit`, `WritePin`, `TogglePin`, `ReadPin`, `WritePort`, `ReadPort`, `SetPullups`, `SetPinPullup`, `SetPinIOC`, `RB_IRQHandler`) branches on `port` with literal `PIC_REG_TRISA` etc. behind `EPIC_REG8(addr)`, producing `inttoptr (i16 <const> to ptr)` in IR. No `tris_addr()`/`port_addr()` helpers, no computed address, no `switch` on port that LLVM emits as `switch` instruction. Use `if (port==GPIOA) ... else if ...` chain as the 87XA file does, with memory-barrier `asm volatile("" ::: "memory")` around RMW where the 87XA file inserted it for the bank probe audit.

- **Port geometry.** `port_width()` returns `3` for `GPIOE` (RE0..RE2), `8` for others (RA/RB/RC/RD up to 8 pins), matching `pic16f88x_gpio.h`’s `port_mask` logic; 87XA’s 6-pin PORTA quirk does not apply.

- **ANSEL handling.** `Init` drives ANSEL/ANSELH via `EPIC_BANK3_WRITE8`/`READ8` with literal names (`ANSEL`, `ANSELH`) through `EPIC_REG8` now that banking is the compiler’s job. Under `epic-cc` the target header’s Bank3 inline-asm is not selected (the `epiccc` include replaces it). Match the in-place file’s `set_ansel_bits` logic but per-pin via literal branches rather than a computed `reg_out` pointer.

- **Pull-ups / IOC.** `SetPinPullup` → `WPUB` (Bank2, 0x95), `SetPinIOC` → `IOCB` (Bank2, 0x96) via `EPIC_BANK2_WRITE8` literal form; again avoid variable pointer.

- **IRQ.** `RB_IRQHandler` as in 87XA epiccc: check `INTCON.RBIF` via `EPIC_REG8(PIC_REG_INTCON)`, read `PORTB`, clear `RBIF` with `EPIC_BIT_CLR`, then call the callback only when `EPIC_AT` not defined. No inline-asm banking.

File header: one-paragraph comment citing DS40001291H §3 and the irparse limitation, same style as the 87XA file.

### 2. `scripts/epic_build.py` - one-line mapping

```py
if path == "pic16f88x-hal/src/peripherals/pic16f88x_gpio.c":
    return "pic16f88x-hal/src/epiccc/pic16f88x_gpio_epiccc.c"
```

Replaces the current passthrough comment. No other family needed; other peripherals already use literal `PIC_REG_*` or bank macros with literal names and assemble cleanly.

### 3. Smoke

- `python3 scripts/epic_build.py build --module pic16f88x-hal --mcu 16F887 --toolchain epic-cc --run` (or the `make` wrapper) produces `build/16F887-blink.hex`. Verify the IR stage contains only `inttoptr i16 <const>` and no `inttoptr i16 %reg`.
- Run the smoke: `blinky` (`tests/example_blink.c`) via `crates/sim` (HAL-4, #60) if the sim harness for 887 is available; otherwise `docs/adding-a-device.md` §4 single `mdb` register read (`stepi` over the init, read back TRISA/PORTA). Either satisfies the ticket’s "or".
- Record any gap that surfaces as a filed issue, same posture as #67 `EPIC_AT` workarounds. Do not silently patch the compiler.

## Verification

- `python3 scripts/epic_build.py build --module pic16f88x-hal --mcu 16F887 --toolchain epic-cc` succeeds; `epic-cc --emit ll` shows no variable `inttoptr`.
- `make test` (host-sim) stays green; `scripts/gen-sfr.py --check` unaffected.
- Smoke hex runs in sim or passes one `mdb` read.

## Risks

- ANSEL/ANSELH banking: if the literal Bank3 path still mis-banks, the probe would surface as wrong TRIS bits. Mitigation is the same `EPIC_BANK3_*` literal form that the 887A file uses for `OPTION_REG`.
- `EPIC_AT` placement differences for globals between 877A and 887 are already exercised by the 877A epic-cc build; reuse `EPIC_AT` as-is and file a gap if the 887 map diverges.
