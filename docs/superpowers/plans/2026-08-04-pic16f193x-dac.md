# DAC for pic16f193x-hal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Status: **implemented and cleared the §4 gate.** This is peripheral #8 in
`docs/pic16f193x-plan.md` §7's roadmap table. Nothing in this document
has been built or verified; register addresses/bit positions were
cross-checked against the installed DFP header before writing (see
Global Constraints), but that is not a substitute for the §4 gate
below actually running.

**Goal:** Land a `HAL_DAC_*` driver for the 5-bit resistor-ladder DAC
(DS41364B §21.0) through the full §4 verification gate of
`docs/adding-a-device.md`: host sim, six-part real-target XC8 build,
and `mdb` `MODE=gpio` register readback.

**Architecture:** Two registers, `DACCON0` (enable/config) and
`DACCON1` (5-bit output value `DACR<4:0>`). No interrupt source on
this device. Output can drive an external pin (`DACOE`) and/or feed
the comparator/ADC as an internal reference. This plan scopes to
VDD-referenced output only; FVR-as-reference is deferred (see
Non-goals). Mirrors the file layout, `HAL_<PERIPH>_*` naming, and
handle-copy convention already used by `pic16f193x_timer1.{h,c}`.

**Tech Stack:** C99, MPLAB XC8 (target build), gcc (host sim build),
CMake, GNU Make.

## Global Constraints

- C99, no compiler extensions in portable code; XC8 inline asm (none
  needed for this peripheral, no banked RMW required) follows the
  root `CLAUDE.md` rules if ever added: no operand constraints, only
  file-scope `static volatile` symbols addressable, leading `_` on
  PIC16 user globals in the asm string, SFRs don't need it, STATUS
  bits numeric not aliased.
- No em-dashes anywhere in code, comments, or docs.
- Every register access is a compile-time-constant `PIC_REG_*` token
  (this family's proven pattern); no runtime-computed SFR address.
- Handle-copy convention: `HAL_DAC_Init` copies the caller's handle
  struct by value, never stores the pointer (matches
  `pic16f193x_timer1.c`'s `HAL_TIMER1_Init`).
- **Standing warning, non-negotiable**: every register bit position in
  this plan was re-derived from DS41364B and cross-checked against the
  installed DFP header's `_DACCON0_<FIELD>_POSN`/`_MASK` and
  `_DACCON1_<FIELD>_POSN`/`_MASK` macros
  (`/opt/microchip/xc8/v3.10/pic/packs/Microchip.PIC12-16F1xxx_DFP/xc8/pic/include/proc/pic16f1937.h`).
  Timer1 shipped with a wrong bit position (`PIC_T1CON_TMR1CS` at bit
  1, copied from `pic16f87xa`'s classic-PIC16 T1CON, when this
  family's real field is bits 7:6) because it was transcribed without
  this cross-check. Never trust a bit position from another family's
  driver or from memory alone. There is no existing DAC driver
  anywhere in this codebase to copy from (confirmed absent in
  `pic16f87xa-hal` and `pic18fxx5x-hal`), so this risk is about
  mis-deriving from the datasheet directly, not about copying a wrong
  value from another family.

## Non-goals (not in this phase)

- FVR as the DAC's positive reference (`DACPSS` = FVR encoding):
  deferred until the FVR plan (`docs/superpowers/plans/2026-08-04-pic16f193x-fvr.md`)
  lands; this driver only supports `DACPSS` = VDD.
- Negative-reference selection beyond VSS (`DACNSS`): DS41364B on this
  device only offers VSS as the negative reference in practice (single
  bit, confirm during implementation whether an alternate encoding
  exists; if the datasheet documents only VSS, `DACNSS` is hardwired
  to 0 in this driver and the field is not exposed in the handle).
- Low-power state (`DACLPS`) tuning: left at its POR default.

/* Bank 2. DACCON0/1, DS41364B Register 21-1/21-2. Verified against
 * the installed DFP header (pic16f1937.h) _DACCON0_*/_DACCON1_*
 * POSN/MASK macros; re-verify against DS41364B before relying on

#define PIC_REG_DACCON0        0x118U

#define PIC_DACCON0_DACNSS     PIC8_BIT(0)   /* DACCON0<0>: negative ref (0=VSS). */
#define PIC_DACCON0_DACPSS_MASK 0x0CU        /* DACCON0<3:2>: positive ref select. */

#define PIC_DACCON0_DACEN       PIC8_BIT(7)  /* DACCON0<7>: master enable. */

#define PIC_DACCON1_DACR_MASK   0x1FU        /* DACCON1<4:0>: 5-bit output value. */

- [ ] **Step 1: Write the driver body**

```c
/**
 * @file    pic16f193x_dac.c
 * @brief   PIC16F193X DAC driver implementation.
 */
#include "peripherals/pic16f193x_dac.h"
#include "pic16f193x_sfr.h"
#include "pic16f193x_platform.h"

HAL_StatusTypeDef HAL_DAC_Init(const DAC_HandleTypeDef *h)
{
    if (!h) return HAL_INVALID;
    if (h->Value > 0x1FU) return HAL_INVALID;

    uint8_t con0 = PIC_DACCON0_DACPSS_VDD;  /* DACNSS=0 (VSS), DACPSS=00 (VDD). */
    if (h->OutputToPin) con0 |= PIC_DACCON0_DACOE;
    PIC8_REG8(PIC_REG_DACCON0) = con0;      /* DACEN left clear until Enable(). */
    PIC8_REG8(PIC_REG_DACCON1) = (uint8_t)(h->Value & PIC_DACCON1_DACR_MASK);

    return HAL_OK;
}

HAL_StatusTypeDef HAL_DAC_DeInit(void)
{
    PIC8_REG8(PIC_REG_DACCON0) = 0x00U;
    PIC8_REG8(PIC_REG_DACCON1) = 0x00U;
    return HAL_OK;
}

HAL_StatusTypeDef HAL_DAC_SetValue(uint8_t value_5bit)
{
    if (value_5bit > 0x1FU) return HAL_INVALID;
    PIC8_REG8(PIC_REG_DACCON1) = (uint8_t)(value_5bit & PIC_DACCON1_DACR_MASK);
    return HAL_OK;
}

HAL_StatusTypeDef HAL_DAC_Enable(void)
{
    PIC8_BIT_SET(PIC8_REG8(PIC_REG_DACCON0), PIC_DACCON0_DACEN);
    return HAL_OK;
}

HAL_StatusTypeDef HAL_DAC_Disable(void)
{
    PIC8_BIT_CLR(PIC8_REG8(PIC_REG_DACCON0), PIC_DACCON0_DACEN);
    return HAL_OK;
}
```

**Files:**

**Interfaces:**

- [ ] **Step 1: Write the example**

```c
/**
 * @file    example_dac.c
 * @brief   DAC smoke test: enable, set a known value, report PASS.
 *
 * @details
 *   The host sim has no real analog output to read back, so this
 *   example only proves the control-register writes took effect (the
 *   §4 gate's `mdb print DACCON0`/`print DACCON1` readback is the
 *   actual verification of correctness, not the sim). Analog output
 *   correctness itself is out of scope for what this example can
 *   prove.
 *
 *   Expected register image (host sim, after init):
 *     DACCON0 = 0x80   (DACEN=1, DACPSS=00 VDD, DACOE=0, DACNSS=0)
 *     DACCON1 = 0x0F   (DACR<4:0> = 15, the test's chosen value)
 *     TRISA   = 0xFE   (RA0 output, harness marker pin)
 *     LATA    = 0x00   (RA0 low until pic8_harness_report drives it)
 */

#include "pic16f193x.h"
#include "pic16f193x_sfr.h"
#include "peripherals/pic16f193x_gpio.h"
#include "peripherals/pic16f193x_dac.h"
#include "core/pic16f193x_wdt_sleep.h"
#include "core/pic8_harness.h"

extern void pic16f193x_harness_halt(void);

int main(void)
{
    pic8_harness_init();

    DAC_HandleTypeDef dac = DAC_HANDLE_DEFAULT;
    dac.Value = 15U;   /* 0x0F, mid-scale of 0-31, arbitrary known value. */
    HAL_StatusTypeDef st = HAL_DAC_Init(&dac);
    if (st != HAL_OK) {
        int rc = pic8_harness_report(0);
        pic16f193x_harness_halt();
        return rc;
    }
    HAL_DAC_Enable();

    uint8_t con0 = PIC8_REG8(PIC_REG_DACCON0);
    uint8_t con1 = PIC8_REG8(PIC_REG_DACCON1);
    uint8_t pass = (con0 == 0x80U) && (con1 == 0x0FU);

    pic8_harness_log("DACCON0=0x%02X DACCON1=0x%02X\n", con0, con1);
    int rc = pic8_harness_report(pass);
    pic16f193x_harness_halt();
    return rc;
}
```

Re-check `pic8_harness_init()`'s exact name/signature against
`example_timer1.c` before finalizing, some examples in this codebase
call an init step, some don't; match whichever is actually established.
