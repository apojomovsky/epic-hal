# epic-fsm PIC16F193X port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `PIC16F193X` as a supported family for `epic-fsm`, module #1
of `docs/superpowers/specs/2026-08-06-pic16f193x-module-rollout-design.md`'s
rollout order, so it builds real-target firmware for all six 193X variants
and CI covers it the same way it already covers PIC16F87XA/PIC18Fxx5x.

**Architecture:** `epic-fsm` has zero HAL dependency (`src/fsm.c` is pure
`<stdint.h>`/`<stdbool.h>` logic, no `#ifdef`, no per-family variant,
confirmed in `epic-fsm/README.md` and `epic-fsm/docs/ARCHITECTURE.md`).
The port is therefore manifest-only: add a `PIC16F193X` family block to
`epic-fsm`'s `epic-common/manifest/modules.toml` entry (`supported` +
`example.PIC16F193X`, reusing the existing family-agnostic
`mcu/target_sizecheck.c`), then prove it with a real XC8 build per variant
and record the footprint the same way the PIC16F877A/PIC18F4550 rows
already are in `docs/ARCHITECTURE.md`. No host-side change: the host
build/tests never varied by family for this module and still don't.

**Tech Stack:** Python 3.11+ (`scripts/epic_build.py`), MPLAB XC8 v3.10
(native, `/opt/microchip/xc8/v3.10/bin`), `Microchip.PIC12-16F1xxx_DFP`.

## Global Constraints

- **No em-dashes.** Not in docs, commit messages, or code comments.
- **Conventional Commits**, scope `pic16f193x` or `fsm`.
- **Every register/toolchain fact gets verified, not assumed**: this
  module touches no registers at all, so the only thing to verify per
  variant is that the real XC8 build actually succeeds and produces a
  `.hex`, not a datasheet fact.
- **Update the docs a change touches**: `epic-fsm/README.md`'s Real
  target section, `epic-fsm/docs/ARCHITECTURE.md`'s Footprint table, and
  this rollout's design doc status line.

## Task 2: Real-target build, all six variants

**Files:** none (build-only task; verifies Task 1's manifest change).

**Interfaces:**
- Consumes: Task 1's manifest entry.
- Produces: six passing `.hex` builds and one flash/RAM measurement,
  which Task 3's docs update depends on.

- [ ] **Step 1: Set up the toolchain PATH**

```bash
export PATH=$PATH:/opt/microchip/xc8/v3.10/bin
which xc8-cc
```

Expected: prints `/opt/microchip/xc8/v3.10/bin/xc8-cc`. If this fails,
stop and check `CLAUDE.md`'s Build & toolchain section rather than
guessing at a path.

- [ ] **Step 2: Build and run all six variants**

```bash
for mcu in 16F1933 16F1934 16F1936 16F1937 16F1938 16F1939; do
  echo "=== $mcu ==="
  python3 scripts/epic_build.py build --module epic-fsm --mcu "$mcu" --run \
    2>&1 | tee "/tmp/epic-fsm-$mcu.log"
done
```

Expected: every one ends with a produced `.hex` and no `xc8-cc` error
lines. `epic_build.py build --run` exits non-zero if `xc8-cc` fails, so a
clean loop exit (check with `echo $?` after, or just watch for `error:`
in the tee'd output) is the pass signal.

- [ ] **Step 3: If any variant fails, stop and diagnose before continuing**

This module has no register access and no bank-sensitive code, so a
failure here would be a genuinely new finding (e.g., a stack-depth or
addressing-mode difference the manifest's `includes`/`hal_sources`
ordering doesn't account for), not a known risk from
`docs/pic16f193x-plan.md` §8. Do not paper over it by narrowing the
`supported` list without understanding why first.

- [ ] **Step 4: Record the footprint for PIC16F1937**

`docs/ARCHITECTURE.md`'s existing table uses one representative part per
family (PIC16F877A for PIC16F87XA, PIC18F4550 for PIC18Fxx5x); do the
same here with PIC16F1937 (the part named in `docs/pic16f193x-plan.md`
§1 as the one the user actually targets).

```bash
python3 scripts/epic_build.py report --log /tmp/epic-fsm-16F1937.log
```

Expected: a JSON object with the program-space and data-space usage
parsed from the XC8 build log's Memory Summary. Note the exact numbers
(and compute their percentage against 1937's 8192-word / 512 B capacity)
for Task 3.
