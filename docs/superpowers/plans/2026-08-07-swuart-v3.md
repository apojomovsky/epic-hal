# epic-swuart v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `epic-swuart`'s v2 software-scheduled timing engine with
a CCP (Capture/Compare) hardware-assisted engine, so RX start-bit sync
and TX bit generation no longer depend on interrupt-service latency, and
so the module actually fits its real interrupt cycle budget (v2's real
compiled ISR measured 1019 cycles against a 521-cycle budget on
PIC16F877A, 196% over).

**Architecture:** Each channel owns a dedicated pair of CCP modules: one
in Capture mode for RX (hardware timestamps the start-bit edge into
`CCPRx`, immune to ISR latency), one in Compare mode for TX (hardware
toggles the pin at a scheduled absolute Timer1 count, decoupling the
physical edge from ISR execution time). Timer1 free-runs continuously as
the shared time base; every deadline is an absolute 16-bit Timer1 count,
not a relative countdown. Real per-family CCP module counts cap channel
capacity: 1 channel on PIC16F87XA/PIC18Fxx5x (2 CCP modules each), 2 on
PIC16F193X (5 CCP modules, 1 spare).

**Tech Stack:** C99, MPLAB XC8, CMake + ctest (host sim, with a disclosed
new testing gap: no family's simulator models CCP capture/compare, tests
must manually poke the state and call the IRQ handler directly), the
manifest for real-target builds, `scripts/ci-target-sim.sh` for the
real-target `mdb` gate.

**Design spec:** `docs/superpowers/specs/2026-08-07-swuart-v3-design.md`.

## Global Constraints

- **No em-dashes.**
- **9600 baud only, 8N1, unchanged public API.**
  `EPIC_SWUART_Init/DeInit/Write/Read/GetErrorCount`, the ring-buffered
  non-blocking shape, and the one-error-counter-per-handle model are
  unchanged from v1/v2.
- **A real, load-bearing HAL discovery that changes this plan's shape:**
  `EPIC_WEAK` (used on every `CCPn_IRQHandler`/`TIMER1_IRQHandler`
  declaration) expands to nothing at all on real-target builds
  (`pic16f87xa-hal/include/target/pic16f87xa_platform.h:20`, confirmed
  the same for the other two families). Weak-symbol override is a
  host-build-only convenience; on real hardware the CCP driver's own
  `CCP1_IRQHandler`/`CCP2_IRQHandler` (and `CCP3`-`CCP5` on PIC16F193X)
  are the *only* definitions that can exist, application code cannot
  provide its own. `epic_swuart.c` must hook CCP events through the
  existing `EventCallback` function-pointer field in `CCP_HandleTypeDef`
  (the same mechanism v2 used for `TIMER1_HandleTypeDef.OverflowCallback`),
  never by trying to define its own `CCPn_IRQHandler`.
- **Straight-line dispatch still matters, but the shape changed.** v2's
  real-hardware finding that array-of-pointers-plus-loop dispatch costs
  far more than straight-line, named-slot dispatch
  (`docs/superpowers/plans/probe-swuart-v2-isr-budget.md`) is not
  reversed by this redesign. Each CCP module's `EventCallback` is
  already a fixed, compile-time-known function per channel slot (there
  is no shared multi-channel dispatch loop to get wrong this time), so
  this constraint is satisfied by construction, not by a rule to
  remember while writing code.
- **CCP resource allocation is fixed per family, not runtime-configurable:**
  PIC16F87XA / PIC18Fxx5x: CCP1 = RX, CCP2 = TX, exactly one channel.
  PIC16F193X: CCP1 = RX-A, CCP2 = TX-A, CCP3 = RX-B, CCP4 = TX-B, CCP5
  unused, exactly two channels.
- **`EPIC_SWUART_MAX_CHANNELS` is resolved by family detection inside
  `epic_swuart.h`**, the same `#if defined(...)` pattern the module's
  own tests already use, not a user-overridable macro. `EPIC_SWUART_Init`
  returns `EPIC_INVALID` once that real per-family ceiling is reached.
- **RX/TX pins are now fixed by the CCP instance, not freely chosen.**
  Each CCP module's capture/compare pin is wired to one specific silicon
  pin (e.g. PIC16F87XA: CCP1 = RC2, CCP2 = RC1, per
  `pic16f87xa_ccp.h`'s own doc comment). `EPIC_SWUART_Init` must validate
  the caller's `tx_port`/`tx_pin`/`rx_port`/`rx_pin` match the fixed pin
  for that channel slot's CCP instances and return `EPIC_INVALID`
  otherwise, rather than silently accepting a mismatched pin. Look up
  PIC18Fxx5x's and PIC16F193X's exact pin-per-instance mapping in their
  own `MANUAL.md`/datasheet section before writing that family's
  validation (PIC18Fxx5x's CCP1/CCP2 pins match PIC16F87XA's per
  `pic18fxx5x_ccp.h`'s own doc comment, RC2/RC1; PIC16F193X's mapping is
  not yet in this plan's own research and must be looked up fresh, DS41364B
  §15.0).
- **One bit period in instruction cycles:** `round(FOSC_HZ / 4 / baud)`,
  521 cycles at 9600 baud/20 MHz. Same formula v1/v2 already used.
  Timer1 stays prescaler 1:1.
- **Timer1 is free-running, never reset or rewritten per-bit.** All
  deadlines are absolute 16-bit Timer1 counts; wraparound is handled for
  free by unsigned 16-bit subtraction/addition, no explicit rollover
  logic. Still exclusively owned by `epic-swuart` while any channel is
  active.
- **A schedule-miss hazard that needs a lead margin.** Arming a deadline
  that is already in the past (or too close to "now") by the time
  `EPIC_CCP_SetCompare`/`SetMode` finish executing means the match is
  silently missed until Timer1 wraps all the way around, roughly 13ms at
  20 MHz, a much worse failure than a late tick. The very first arm of a
  frame (from `EPIC_SWUART_Write`, not from inside an ISR already
  tracking a running deadline) must add a small fixed lead,
  `SWUART_LEAD_CYCLES = 120` (raised from an initial guess of 40 after
  Task 2's real probe measured 73-95 cycles of dispatch-to-handler
  latency alone on PIC16F877A, comfortably above the old guess; 120
  keeps real margin above the largest measured value,
  `docs/superpowers/plans/probe-swuart-v3-ccp-cost.md`).
- **A related, second schedule-miss hazard Task 2's probe reproduced
  live, at `EPIC_CCP_Init` time rather than steady-state re-arm time:**
  `EPIC_CCP_Init` calls table-driven `EPIC_IRQ_ClearFlag`/`Enable`
  *before* writing `CCPRx`/`CCPxCON`, costing roughly 150-250 cycles
  per instance. If a channel's TX CCP module were initialised with a
  live, near-term compare deadline already armed, that setup cost alone
  could cause the very first match to be missed before the module is
  even configured. Tasks 3-4's design already avoids this by
  construction, not by accident: `EPIC_SWUART_Init` brings the TX CCP
  module up in `CCP_MODE_OFF` (no deadline to miss), and the first real
  deadline is only armed later, by `EPIC_SWUART_Write`, using the cheap
  `EPIC_CCP_SetCompare`/`SetMode` path (not `EPIC_CCP_Init`) plus
  `SWUART_LEAD_CYCLES`. Do not "simplify" this later by having `Init`
  arm a live TX deadline directly; that would reintroduce the exact
  hazard this probe reproduced.
- **Host-sim cannot model CCP capture/compare at all**, confirmed by
  reading `pic16f87xa-hal/CMakeLists.txt`: `pic16f87xa_ccp.c` compiles
  unchanged into the host build with zero simulated hardware behind it.
  Tests manually write the simulated register state and call
  `CCPn_IRQHandler()` directly, the same category of workaround v2 used
  for the RBIF/IOC gap. Extending the simulators is explicitly out of
  scope.
- **A documented, not fixed, hazard:** `EPIC_GPIO_WritePin` on
  PIC16F87XA does a physical-PORT read-modify-write (no LAT register on
  that family). Note it in Task 9's documentation; do not fix the GPIO
  HAL here.
- **Conventional Commits, trailing newline, no trailing whitespace,
  commit after every task.**

(`pic16_irq_dispatch.c` and its per-family equivalents) already confirmed
the flag is set before calling the handler at all. Without this fix, CCP
interrupts pay the identical redundant cost Timer1's did.

- [ ] **Step 1: Write a real probe program using the actual CCP driver**

Outside the repo, `/tmp/swuart-v3-probe/probe.c`, PIC16F877A, using the
real `pic16f87xa-hal` sources (not a mirror):

```c
#include <xc.h>
#include "pic16f87xa.h"
#include "pic16f87xa_sfr.h"
#include "peripherals/pic16f87xa_gpio.h"
#include "peripherals/pic16f87xa_timer1.h"
#include "peripherals/pic16f87xa_ccp.h"
#include "core/pic16_irq.h"

#pragma config FOSC = HS
#pragma config WDTE = OFF
#pragma config PWRTE = ON
#pragma config BOREN = ON
#pragma config LVP = OFF
#pragma config CPD = OFF
#pragma config WRT = OFF
#pragma config CP = OFF

static uint16_t g_deadline = 0;

static void on_ccp2_compare(void)
{
    /* Representative TX compare-event cost: one mode decision, one
     * GPIO-free CCPxCON write, one CCPRx write, one shift/counter
     * update, matching tx_compare_event's real shape from Task 4. */
    static uint8_t shift = 0x41u;
    static uint8_t bit_index = 0u;
    CCP_ModeTypeDef next_mode = (shift & 0x01u) ? CCP_MODE_COMPARE_SET : CCP_MODE_COMPARE_CLEAR;
    shift >>= 1;
    bit_index++;
    if (bit_index >= 8u) bit_index = 0u;
    g_deadline = (uint16_t)(g_deadline + 521u);
    EPIC_CCP_SetCompare(CCP_INSTANCE_2, g_deadline);
    EPIC_CCP_SetMode(CCP_INSTANCE_2, next_mode);
}

static void on_ccp1_capture(void)
{
    /* Representative RX capture-event cost: read the capture register,
     * compute the half-bit deglitch deadline (261 = round(521/2), the
     * mid-start-bit confirm point, not d0's sample point, see Task 5's
     * real implementation for why those are two separate hops), arm
     * compare mode. Cycle cost is identical either way; this probe only
     * measures instruction count, not correctness, but the comment
     * should not misdescribe what the real code does. */
    uint16_t edge = EPIC_CCP_GetCapture(CCP_INSTANCE_1);
    g_deadline = (uint16_t)(edge + 261u);
    EPIC_CCP_SetCompare(CCP_INSTANCE_1, g_deadline);
    EPIC_CCP_SetMode(CCP_INSTANCE_1, CCP_MODE_COMPARE_SOFT_IF);
}

void main(void)
{
    TIMER1_HandleTypeDef t1 = TIMER1_HANDLE_DEFAULT;
    EPIC_TIMER1_Init(&t1);
    EPIC_TIMER1_Start(&t1);

    CCP_HandleTypeDef ccp2 = { .Instance = CCP_INSTANCE_2, .Mode = CCP_MODE_COMPARE_CLEAR,
                               .CompareValue = 521u, .EventCallback = on_ccp2_compare };
    EPIC_CCP_Init(&ccp2);

    CCP_HandleTypeDef ccp1 = { .Instance = CCP_INSTANCE_1, .Mode = CCP_MODE_CAPTURE_FALLING,
                               .CompareValue = 0u, .EventCallback = on_ccp1_capture };
    EPIC_CCP_Init(&ccp1);

    EPIC_IRQ_Restore(1);
    for (;;) { }
}
```

- [ ] **Step 1: Replace the file header doc comment and add the
  per-family max-channels resolution**

```c
/**
 * @file    epic_swuart.h
 * @brief   Bit-banged full-duplex UART, CCP hardware capture/compare
 *          timing. Channel capacity is a real per-family hardware
 *          ceiling (CCP module count), not configurable: 1 channel on
 *          PIC16F87XA/PIC18Fxx5x, 2 on PIC16F193X.
 *
 * @details
 *   RX uses CCP Capture mode to hardware-timestamp the start-bit edge,
 *   TX uses CCP Compare mode to hardware-toggle the pin at a scheduled
 *   Timer1 count. Both are immune to ISR service latency: the physical
 *   event happens in hardware at the programmed instant regardless of
 *   how late software reprograms the *next* one. Timer1 free-runs
 *   continuously as the shared time base; see docs/ARCHITECTURE.md.
 *   9600 baud only is validated; 8 data bits, no parity, 1 stop bit,
 *   not configurable. Non-blocking, ring-buffered.
 *
 *   This module owns Timer1 and the CCP instances listed in
 *   docs/ARCHITECTURE.md for as long as any channel is active: do not
 *   also drive Timer1 or those CCP instances directly from application
 *   code while a channel is initialised. RX/TX pins are fixed by which
 *   physical pin each CCP instance is wired to, not freely choosable;
 *   EPIC_SWUART_Init validates the caller's pins match.
 */
#ifndef EPIC_SWUART_H
#define EPIC_SWUART_H

#include <stdint.h>
#include <stddef.h>
#include "epic_hal.h"

#if defined(PIC16F1933) || defined(PIC16F1934) || defined(PIC16F1936) || \
    defined(PIC16F1937) || defined(PIC16F1938) || defined(PIC16F1939)
#define EPIC_SWUART_MAX_CHANNELS 2u
#else
#define EPIC_SWUART_MAX_CHANNELS 1u
#endif
```

- [ ] **Step 2: Replace the RING_SZ block's surrounding context and the
  handle struct**

Keep the existing `EPIC_SWUART_RING_SZ`/`_Static_assert` block
unchanged (still `8u` default, still power-of-two enforced). Replace
the struct:

```c
typedef struct {
    GPIO_TypeDef tx_port;
    uint16_t     tx_pin;
    GPIO_TypeDef rx_port;
    uint16_t     rx_pin;

    volatile uint8_t  tx_state;
```

```c
/* Arms the mode for the *next* compare match, not the one that just
 * fired (hardware already toggled the pin per whatever was armed
 * ahead of time; this function's job is only to decide what happens
 * at the deadline it is about to write). Traced against 'A' = 0x41,
 * LSB first (start=0, d0=1, d1..d5=0, d6=1, d7=0, stop=1): Write()
 * arms CLEAR for the start bit; this handler then arms SET (d0=1),
 * CLEAR x5 (d1..d5=0), SET (d6=1), CLEAR (d7=0), SET (stop=1), in that
 * order, landing back in TX_IDLE exactly at the stop bit's deadline. */
static void tx_compare_event(EPIC_SWUART_HandleTypeDef *h, CCP_InstanceTypeDef tx_inst)
{
    CCP_ModeTypeDef next_mode;

    switch (h->tx_state) {
    case TX_IDLE:
        if (h->tx_count == 0u) {
            EPIC_CCP_SetMode(tx_inst, CCP_MODE_OFF);
            return;
        }
        h->tx_shift = h->tx_ring[h->tx_tail];
        h->tx_tail = (uint8_t)((h->tx_tail + 1u) & (EPIC_SWUART_RING_SZ - 1u));
        h->tx_count--;
        h->tx_bit_index = 0u;
        next_mode = CCP_MODE_COMPARE_CLEAR;
        h->tx_state = TX_DATA;
        break;
    case TX_DATA:
        next_mode = (h->tx_shift & 0x01u) ? CCP_MODE_COMPARE_SET : CCP_MODE_COMPARE_CLEAR;
        h->tx_shift >>= 1;
        h->tx_bit_index++;
        if (h->tx_bit_index >= 8u) h->tx_state = TX_STOP;
        break;
    case TX_STOP:
    default:
        next_mode = CCP_MODE_COMPARE_SET;
        h->tx_state = TX_IDLE;
        break;
    }

    h->tx_deadline = (uint16_t)(h->tx_deadline + g_cycles_per_bit);
    EPIC_CCP_SetCompare(tx_inst, h->tx_deadline);
    EPIC_CCP_SetMode(tx_inst, next_mode);
}
```

```c
static void rx_push(EPIC_SWUART_HandleTypeDef *h, uint8_t byte)
{
    if (h->rx_count >= EPIC_SWUART_RING_SZ) {
        h->error_count++;
        return;
    }
    h->rx_ring[h->rx_head] = byte;
    h->rx_head = (uint8_t)((h->rx_head + 1u) & (EPIC_SWUART_RING_SZ - 1u));
    h->rx_count++;
}

static uint16_t g_test_capture_value = 0u;
void swuart_test_set_capture(uint16_t value) { g_test_capture_value = value; }
static uint16_t test_get_capture(void) { return g_test_capture_value; }

#endif

static void on_rx_event_a(void)
{
    EPIC_SWUART_HandleTypeDef *h = g_chan_a;

    if (h->rx_state == RX_IDLE) {
        /* Capture-mode event: a start-bit falling edge just arrived,
         * hardware-timestamped, immune to how late this handler
         * actually runs. */
        uint16_t edge_time = test_get_capture();
        /* Half a bit period: the mid-start-bit deglitch confirm point,
         * matching v1/v2's own on_rx_edge_start exactly (rx_ticks_left
         * = g_cycles_per_bit / 2u there). This is NOT d0's sample
         * point yet; the RX_CONFIRM_START branch below adds one more
         * full bit period on top of this once the confirm passes,
         * landing at edge_time + 1.5 * cycles_per_bit for d0, the same
         * two-hop sequence v1/v2 used. Collapsing this into a single
         * 1.5x hop (an earlier draft of this exact function did) skips
         * the deglitch check entirely: at 1.5x post-edge the pin
         * reflects d0's own value, not the start bit's stability, so a
         * one-hop version would silently stop rejecting noise starts. */
        h->rx_deadline = (uint16_t)(edge_time + g_cycles_per_bit / 2u);
        h->rx_state = RX_CONFIRM_START;
        EPIC_CCP_SetCompare(SWUART_CCP_RX, h->rx_deadline);
        EPIC_CCP_SetMode(SWUART_CCP_RX, CCP_MODE_COMPARE_SOFT_IF);
        return;
    }

    if (h->rx_state == RX_CONFIRM_START) {
        if (EPIC_GPIO_ReadPin(h->rx_port, h->rx_pin) != GPIO_PIN_RESET) {
            h->rx_state = RX_IDLE; /* noise, not a real start bit */
            EPIC_CCP_SetMode(SWUART_CCP_RX, CCP_MODE_CAPTURE_FALLING);
            return;
        }
        h->rx_shift = 0u;
        h->rx_bit_index = 0u;
        h->rx_state = RX_DATA0;
        h->rx_deadline = (uint16_t)(h->rx_deadline + g_cycles_per_bit);
        EPIC_CCP_SetCompare(SWUART_CCP_RX, h->rx_deadline);
        return;
    }

    uint8_t sample = (EPIC_GPIO_ReadPin(h->rx_port, h->rx_pin) == GPIO_PIN_SET) ? 1u : 0u;

    if (h->rx_state == RX_STOP) {
        if (sample != 0u) {
            rx_push(h, h->rx_shift);
        } else {
            h->error_count++;
        }
        h->rx_state = RX_IDLE;
        EPIC_CCP_SetMode(SWUART_CCP_RX, CCP_MODE_CAPTURE_FALLING);
        return;
    }

    h->rx_shift = (uint8_t)((h->rx_shift >> 1) | (sample ? 0x80u : 0u));
    h->rx_bit_index++;
    h->rx_state = (h->rx_bit_index < 8u) ? (uint8_t)(RX_DATA0 + h->rx_bit_index) : RX_STOP;
    h->rx_deadline = (uint16_t)(h->rx_deadline + g_cycles_per_bit);
    EPIC_CCP_SetCompare(SWUART_CCP_RX, h->rx_deadline);
}
```

## What this plan deliberately does not do

- Change the public API, framing, baud-rate scope, or error-handling
  contract inherited from v1/v2.
- Support more than one channel on PIC16F87XA/PIC18Fxx5x, or more than
  two on PIC16F193X. A real hardware ceiling, not a configurable limit.
- Extend the host simulators to model CCP capture/compare. A real,
  separate, disclosed gap.
- Use PWM mode or any CCP capability beyond capture and compare.
- Fix the `EPIC_GPIO_WritePin` RMW hazard on PIC16F87XA. Documented,
  not addressed.
- Touch the v1 fix wave's interrupt-dispatch group-read optimization
  (`pic16_irq_dispatch.c` and equivalents); it is correct and orthogonal
  to Task 1's CCP-handler fix, which operates one level deeper.
