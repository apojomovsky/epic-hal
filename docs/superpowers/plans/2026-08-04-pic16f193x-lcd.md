# LCD Segment Driver for pic16f193x-hal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Status: **implemented and cleared the §4 gate.** Peripheral #12 in
`docs/pic16f193x-plan.md` §7's roadmap table. **This is the largest
and highest-risk peripheral in the whole remaining roadmap** (12 data
registers, no existing driver anywhere in this codebase to
cross-check against, confirmed absent in both `pic16f87xa-hal` and
`pic18fxx5x-hal`). Budget real datasheet-reading time before
implementing; don't rush this one.

**Goal:** Land a `EPIC_LCD_*` driver for the LCD segment driver
(DS41364B LCD chapter) through the §4 gate, scoped to internal
reference / static-or-1:4-mux / Type-A-waveform only (Non-goals covers
the rest of the feature surface).

**Architecture:** 24 segments / 4 commons on the 1937/1939 (40/44-pin),
16 segments / 4 commons on 1933/1936/1938 (28-pin), per
`docs/pic16f193x-plan.md` §1's device table; a new per-device
`PIC16F193X_FAMILY_LCD_SEGMENTS` capability macro in `pic16f193x.h`
(following the existing `PIC16F193X_FAMILY_ADC_CH` pattern) gates
this. API is pixel-level (`EPIC_LCD_SetSegment(seg, com, bool)`,
`EPIC_LCD_Clear()`), not a character/digit-rendering abstraction (that
belongs in an application-level layer, out of scope for this HAL).

**Tech Stack:** C99, MPLAB XC8, gcc (host sim), CMake, GNU Make.

## Global Constraints

- C99, no compiler extensions. No em-dashes anywhere.
- Every register access is a compile-time-constant `PIC_REG_*` token.
- Handle-copy convention: copy by value, never store the pointer.
- **Standing warning**: every bit position here was re-derived from
  DS41364B and cross-checked against the installed DFP header's
  `_LCDCON_`/`_LCDPS_`/`_LCDREF_`/`_LCDCST_`/`_LCDRL_`/`_LCDSE0_`/
  `_LCDSE1_`/`_LCDSE2_`/`_LCDDATA0_` `_POSN`/`_MASK` macros
  (`/opt/microchip/xc8/v3.10/pic/packs/Microchip.PIC12-16F1xxx_DFP/xc8/pic/include/proc/pic16f1937.h`).
  Timer1 shipped with a wrong bit position (`PIC_T1CON_TMR1CS` at bit
  1, copied from `pic16f87xa`'s classic-PIC16 T1CON, real field is
  bits 7:6) from a transcription without this cross-check. This
  peripheral has the largest register set of any in the family and no
  existing driver to cross-check against; every field below needs its
  own independent DS41364B confirmation, not just the DFP POSN/MASK
  numbers.
- The LCD chapter was NOT covered by `docs/pic16f193x-plan.md` §1's
  DS80000479 errata summary (that summary only checked ADC/ECCP/
  Timer1-gate/EUSART/MSSP); independently re-check DS80000479 (or
  whatever current errata document applies) for LCD-specific silicon
  issues before implementing, don't assume "no errata" just because
  none happened to be flagged in this plan's research pass.

## Non-goals (not in this phase)

- External reference-ladder capacitors (`LCDREF`'s `VLCD1PE`/
  `VLCD2PE`/`VLCD3PE` pin-enable bits stay 0; internal charge-pump
  reference only). `LCDRL`'s A/B-phase timing bits use DS41364B's
  recommended default values, not user-configurable this phase.
- Multiplex modes beyond whichever DS41364B recommends as the
  simplest working default (confirm during implementation whether
  that's static or 1:4; this plan does not commit to one without that
  confirmation, see Task 3).
- Type-B waveform (Type-A only, the more common default per typical
  segment-LCD datasheets; confirm against DS41364B during
  implementation, don't assume without checking).
- Character/digit-rendering abstraction: this HAL is pixel-level only.

- [ ] **Step 1: Write the driver body**

```c
/**
 * @file    pic16f193x_lcd.c
 * @brief   PIC16F193X LCD segment driver implementation.
 */
#include "peripherals/pic16f193x_lcd.h"
#include "pic16f193x_sfr.h"
#include "pic16f193x_platform.h"

static void (*s_lcd_cb)(void);

static uint16_t lcddata_reg_addr(uint8_t com)
{
    /* One LCDDATAn register per common line's worth of 8 segments;
     * confirm this seg-to-register mapping against DS41364B's actual
     * SEGnCOMm bit layout before trusting the arithmetic below, this
     * plan asserts LCDDATA(seg/8) holds bit (seg%8) for common com,
     * but the real layout may interleave seg/com differently, verify
     * against the DFP header's _LCDDATA0_SEG0COM0_ naming pattern for
     * every register, not just LCDDATA0. */
    (void)com;
    return PIC_REG_LCDDATA0;   /* Placeholder base; Task 4 Step 2 computes the real offset per (seg, com). */
}

EPIC_StatusTypeDef EPIC_LCD_Init(const LCD_HandleTypeDef *h)
{
    if (!h) return EPIC_INVALID;
    if (h->Contrast > 0x07U) return EPIC_INVALID;

    PIC8_REG8(PIC_REG_LCDCST) = h->Contrast & PIC_LCDCST_LCDCST_MASK;
    PIC8_REG8(PIC_REG_LCDREF) = 0x00U;   /* No external ladder caps this phase. */
    PIC8_REG8(PIC_REG_LCDRL) = 0x00U;    /* Datasheet-default timing; re-derive the real default value against DS41364B, 0x00 is a placeholder, not confirmed. */
    /* LMUX/WFT/BIASMD values must be re-derived per Task 3 Step 1's
     * instruction before this line is finalized; 0x00 (static mode,
     * Type-A if WFT=0 means Type-A) is this plan's best guess, not
     * independently confirmed. */
    PIC8_REG8(PIC_REG_LCDPS) = 0x00U;
    PIC8_REG8(PIC_REG_LCDCON) = PIC_LCDCON_LCDEN;

    for (uint8_t i = 0U; i < 12U; i++) {
        PIC8_REG8((uint16_t)(PIC_REG_LCDDATA0 + i)) = 0x00U;
    }

    uint8_t se_mask = (PIC16F193X_FAMILY_LCD_SEGMENTS >= 24U) ? 0xFFU : 0x00U;
    PIC8_REG8(PIC_REG_LCDSE0) = 0xFFU;   /* SE0-7 always available. */
    PIC8_REG8(PIC_REG_LCDSE1) = (PIC16F193X_FAMILY_LCD_SEGMENTS >= 16U) ? 0xFFU : 0x00U;
    PIC8_REG8(PIC_REG_LCDSE2) = se_mask;

    s_lcd_cb = 0;
    return EPIC_OK;
}

EPIC_StatusTypeDef EPIC_LCD_DeInit(void)
{
    PIC8_REG8(PIC_REG_LCDCON) = 0x00U;
    for (uint8_t i = 0U; i < 12U; i++) {
        PIC8_REG8((uint16_t)(PIC_REG_LCDDATA0 + i)) = 0x00U;
    }
    s_lcd_cb = 0;
    return EPIC_OK;
}

EPIC_StatusTypeDef EPIC_LCD_SetSegment(uint8_t seg, uint8_t com, uint8_t on)
{
    if (seg >= PIC16F193X_FAMILY_LCD_SEGMENTS || com >= LCD_COMMONS) return EPIC_INVALID;

    /* Wait for a write-allowed window per DS41364B's documented
     * LCDDATA write-timing requirement (LCDPS<WA>), a real
     * correctness constraint, not optional; bounded spin, not
     * unconditional, to avoid hanging if WA never asserts due to a
     * misconfigured LCDEN/clock. */
    uint16_t guard = 0U;
    while (!(PIC8_REG8(PIC_REG_LCDPS) & PIC_LCDPS_WA) && guard < 10000U) { guard++; }
    if (guard >= 10000U) return EPIC_ERROR;

    /* seg-to-(register,bit) mapping: re-derive against DS41364B's
     * actual SEGnCOMm layout before trusting this arithmetic (see
     * lcddata_reg_addr's note above); this plan assumes register
     * index = seg / 8, bit index = seg % 8, one LCDDATAn register
     * covers 8 segments for a SINGLE common line, meaning the driver
     * actually needs LCD_COMMONS separate register RANGES, not one
     * flat 12-register array indexed by seg alone. Given 12 registers
     * total / 4 commons = 3 registers per common, re-derive the real
     * indexing scheme (likely register = com*3 + seg/8, bit = seg%8,
     * for a 24-segment device; for a 16-segment device fewer
     * registers are touched) directly from the DFP header's
     * _LCDDATA0_SEG0COM0_ through _LCDDATA11_ naming before shipping
     * this function, the placeholder arithmetic below is NOT
     * confirmed correct and is the single highest-risk line in this
     * entire plan. */
    uint16_t reg = (uint16_t)(PIC_REG_LCDDATA0 + (com * 3U) + (seg / 8U));
    uint8_t bit = (uint8_t)(seg % 8U);

    uint8_t val = PIC8_REG8(reg);
    if (on) val |= (uint8_t)(1U << bit);
    else val &= (uint8_t)~(1U << bit);
    PIC8_REG8(reg) = val;

    return EPIC_OK;
}

EPIC_StatusTypeDef EPIC_LCD_Clear(void)
{
    for (uint8_t i = 0U; i < 12U; i++) {
        PIC8_REG8((uint16_t)(PIC_REG_LCDDATA0 + i)) = 0x00U;
    }
    return EPIC_OK;
}

uint8_t EPIC_LCD_IsActive(void)
{
    return (PIC8_REG8(PIC_REG_LCDPS) & PIC_LCDPS_LCDA) ? 1U : 0U;
}

void LCD_IRQHandler(void)
{
    if (s_lcd_cb) s_lcd_cb();
}
```

**This task carries the plan's single highest-risk unresolved item**:
the `seg`-to-`(LCDDATAn, bit)` mapping in `EPIC_LCD_SetSegment` is
explicitly flagged as unconfirmed placeholder arithmetic in the code
