# Plan: epic-mcp23x17 (MCP23017/MCP23S17 16-bit I/O expander)

Date: 2026-08-12. Status: in progress.

A full module for the Microchip MCP23017 (I2C) and MCP23S17 (SPI)
16-bit remote I/O expander (DS20001952), on top of the HAL via the
existing epic-bus transport layer, per the repo's module anatomy
(README + docs, host-testable via CMake, real-target via the manifest
+ epic_build, one PR, merge-as-is when CI green).

## Datasheet facts the module encodes (DS20001952E)

- 16 pins: GPA0-7 + GPB0-7, defaults to input; each port has its own
  register set. A port register pair is sequential when
  IOCON.BANK=0 (the module's default: IOCON is one register, banked
  layout not used).
- Registers (BANK=0, sequential): IODIR 0x00/01 (1=input),
  IPOL 0x02/03 (1=invert), GPINTEN 0x04/05, DEFVAL 0x06/07,
  INTCON 0x08/09 (1=compare-to-default, 0=pin-change), IOCON 0x0A,
  GPPU 0x0B/0C, INTF 0x0D/0E (RO), INTCAP 0x0F/10 (RO), GPIO 0x11/12,
  OLAT 0x13/14.
- IOCON bits: BANK, MIRROR, SEQOP, DISSLW, HAEN (SPI only), ODR,
  INTPOL.
- MCP23017 I2C: 7-bit device address 0b0100A2A1A0 (write byte
  0x40|A2A1A0, read 0x41|A2A1A0). The epic-bus I2C mem idiom
  (dev, reg, data) matches exactly.
- MCP23S17 SPI: the transaction is CS low, control byte, reg,
  data..., CS high, where the control byte is 0b0100_0A2A1A0 for
  write and 0b0100_1A2A1A0 for read (HAEN=0: A2A1A0=000). The
  epic-bus SPI mem idiom sends reg as the first byte, so the SPI
  transport builds its own transactions from epic-bus's raw SPI ops
  (select/exchange/deselect), which need ops getters added to
  epic-bus (a small extension: epic_bus_get_i2c_ops/get_spi_ops).

## Module design

- `epic-mcp23x17/`: include/epic_mcp23x17.h (public), src/ (one
  family-agnostic .c), tests/ (host ctest), examples/ (target
  example), docs/ARCHITECTURE.md + API.md, README.md.
- The public API: an expander handle carrying a transport (the
  register read/write callbacks + the device address), plus:
  - `EPIC_MCP23X17_Init/DeInit` with a transport; convenience
    constructors for the I2C (epic_bus) and SPI (epic_bus) defaults.
  - 16-bit and per-port accessors: direction, polarity, pull-ups,
    GPIO read/write, output-latch read, all via a `port` enum
    (PORT_A/PORT_B) and 16-bit composite helpers.
  - IOCON configuration (mirror, sequential-off, slew, HAEN, ODR,
    INTPOL).
  - Interrupt support: GPINTEN/DEFVAL/INTCON config + INTF/INTCAP
    readback (the clear-by-read semantics documented).
  - Every accessor returns a status (bus ACK/NACK surfaced).
- The transport seam mirrors epic-bus's own: the module's default
  transports wrap epic-bus's mem ops (I2C) and raw SPI ops
  (MCP23S17 opcode); the host test injects a mock device transport.

## Testing

- Host (CMake + ctest): a mock MCP23X17 device (a register model with
  the I2C/SPI framing via the epic-bus ops seam: the mock registers
  as the epic-bus i2c/spi ops, so the FULL module+epic-bus+mock stack
  is exercised). Covers: register R/W framing, direction/polarity/
  pull-up/GPIO/OLAT semantics, the 16-bit composite helpers, IOCON
  config, the interrupt enable/flag/capture flow, and the device
  NACK error paths.
- Real-target: the manifest entry + example; the matrix builds it for
  every family MCU; a 16F877A mdb gate exercises the init + a
  register round-trip through the sim SSP (the MSSP data path is
  unmodeled, so the gate is bounded to the config/init paths, same
  as the bus gate).
