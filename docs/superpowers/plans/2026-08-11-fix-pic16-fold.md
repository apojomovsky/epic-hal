# Fix the PIC16 add/sub carry-fold (issue #34)

Status: **approved 2026-08-11, in progress**.

## Problem

`epic-math`'s PIC16 `pic_math_add_u16` / `pic_math_sub_u16` fold the
low-byte carry/borrow into the high-byte addend via the
`btfsc/btfss STATUS,0; incfsz b_hi,w; addwf/subwf a_hi,w` idiom. When
`b_hi == 0xFF` and the low add carries (or borrows), `incfsz` wraps to
0 and **skips** the addwf/subwf, so `r_hi` is stored as 0 instead of
`a_hi`. Verified by instruction-level simulation: `add_u16(0x0101,
0xFFFF)` returns `0x0000` (correct: `0x0100`), `sub_u16(0x0102, 0xFFFF)`
returns `0x0003` (correct: `0x0103`); the edge class (b_hi==0xFF with
incoming carry/borrow and a_hi != 0) is wrong in 8.3M of 16.7M cases.

The carry/borrow OUT is already correct in both functions (C is
preserved through the skip); only the result byte is wrong. The same
fold appears in the PIC16 mul and div asm, but those use in-place
accumulates (`addwf r,f` / `subwf r,f`), where the wrapped 0x100
vanishes mod 256 and C is preserved: they are correct. The negate
cascades use the Z idiom, also correct.

The existing golden vectors miss the class: both current wrap-case
vectors (`{0x0002,0xFFFF,...}`) have `a_hi == 0`, so the skip loses
nothing and the PIC16 mdb gate (which replays the vectors on 16F877A)
passes despite the bug.

## Goal

1. Correct the two folds so the result is right for every input and the
   carry/borrow out stays right.
2. Extend the golden vectors with the wrap class (a_hi != 0, b_hi==0xFF,
   low carry/borrow) so the PIC16 mdb gate is a real regression net.
3. Prove the fix with instruction-level simulation, exhaustive over the
   edge classes.

## Fix design (per-fold, verified by hand-trace)

Replace the incfsz-skip fold with an `addlw 1` fold (no skip) plus an
rlf-based carry save, so the result is `a_hi + b_hi + carry` mod 256
and the carry out is `addwf C OR addend-wrap`:

```asm
; add_u16 fold (C = carry from the low add; mscratch[6] pre-zeroed)
    movf  _pic16_mscratch+3,w   ; W = b_hi
    btfsc STATUS,0
    addlw 1                     ; W = (b_hi + carry) & 0xFF; C = wrap
    rlf   _pic16_mscratch+6,f   ; co bit0 = wrap
    movwf _pic16_mscratch+5     ; folded addend
    movf  _pic16_mscratch+1,w   ; W = a_hi
    addwf _pic16_mscratch+5,w   ; W = a_hi + folded; C = C_add
    movwf _pic16_mscratch+5     ; r_hi
    rlf   _pic16_mscratch+6,f   ; co = (wrap<<1) | C_add
    movf  _pic16_mscratch+6,w
    clrf  _pic16_mscratch+6
    andlw 0x03
    btfss STATUS,2              ; skip setf if no wrap and no C_add
    setf  _pic16_mscratch+6     ; co = 0xFF
```

sub_u16 mirrors it: `subwf` for the folded addend, and the co
normalization skips `setf` only when `(co & 3) == 1` (no borrow, no
wrap) via `sublw 1`.
