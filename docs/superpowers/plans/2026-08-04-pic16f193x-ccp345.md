> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Status: **implemented and cleared the §4 gate.** Peripheral #13 (last) in
`docs/pic16f193x-plan.md` §7's roadmap table. This plan EXTENDS the
CCP1/CCP2 driver
(`docs/superpowers/plans/2026-08-04-pic16f193x-ccp12.md`) rather than
creating a new one; land CCP1/2 first and re-read its actual landed
code (not just its plan doc, which may have changed during that
peripheral's own §4-gate iteration, the same way Timer1's plan had two
real bugs found only during execution) before starting this plan.

**Goal:** Add CCP3 (Enhanced CCP, same shape as CCP1/CCP2), CCP4, and
CCP5 (both plain CCP, no PWM/dead-band/auto-shutdown/steering
registers at all) to the existing `pic16f193x_ccp.{h,c}` driver,
through the §4 gate, capture/compare only (mirrors CCP1/2's scope cut).

**Architecture:** CCP3 is register-identical to CCP1/CCP2
(`CCPR3L/H`, `CCP3CON`, `PWM3CON`, `CCP3AS`, `PSTR3CON`), a third
`CCP_INSTANCE_3` on the same enum. CCP4/CCP5 are materially simpler:
only `CCPRxL/H` + `CCPxCON` exist, no PWM-related registers at all
(confirmed absent from the DFP header, not assumed), so their mode
range is capture/compare only by hardware, not by this driver's
scope-cut choice.

**Tech Stack:** C99, MPLAB XC8, gcc (host sim), CMake, GNU Make.

## Global Constraints

- C99, no compiler extensions. No em-dashes anywhere.
- Every register access is a compile-time-constant `PIC_REG_*` token.
- Handle-copy convention: copy by value, never store the pointer.
- **Standing warning**: every bit position here was re-derived from
  DS41364B and cross-checked against the installed DFP header's
  `_CCP3CON_`/`_PWM3CON_`/`_CCP3AS_`/`_PSTR3CON_`/`_CCP4CON_`/`_CCP5CON_`
  `_POSN`/`_MASK` macros
  (`/opt/microchip/xc8/v3.10/pic/packs/Microchip.PIC12-16F1xxx_DFP/xc8/pic/include/proc/pic16f1937.h`).
  Timer1 shipped with a wrong bit position (`PIC_T1CON_TMR1CS` at bit
  1, copied from `pic16f87xa`'s classic-PIC16 T1CON, real field is
  bits 7:6) from a transcription without this cross-check. `CCP4CON`/
  `CCP5CON`'s missing PWM/AS/PSTR registers were confirmed absent by
  directly checking the DFP header, not assumed from CCP1-3's shape;
  don't let the driver code reference a `PIC_CCP4AS_*` or similar
  macro that doesn't exist for these two plain instances.

## Non-goals (not in this phase)

- Enhanced/multi-output PWM for CCP3 (same cut as CCP1/2, and the
  DS80000479 "ECCP 0%-duty direction-change and port-steering issues"
  errata applies to it for the same reason).
- Any PWM mode for CCP4/CCP5: not just deferred, genuinely absent at
  the register level (confirmed: no `PWM4CON`/`CCP4AS`/`PSTR4CON` or
  `PWM5CON`/`CCP5AS`/`PSTR5CON` exist in the DFP header). Re-verify
  during implementation whether `CCP4M`/`CCP5M`'s mode-select
  encodings include ANY PWM-capable value on this specific device
  (some PIC plain-CCP mode tables reserve encodings for a basic PWM
  mode even without the enhanced registers); if DS41364B's CCP4M/CCP5M
  table shows a PWM encoding, this driver still rejects it this phase,
  consistent with CCP1/2's scope cut, don't silently support it.

## Task 7: Add `example_ccp345.c`

**Files:** Create `pic16f193x-hal/tests/example_ccp345.c`.

- [ ] **Step 1: Write the example**

```c
/**
 * @file    example_ccp345.c
 * @brief   CCP3/CCP4/CCP5 smoke test: all three in compare-set mode,
 *          confirm control-register + compare-value state.
 *
 * @details
 *   Expected register image (host sim, after init):
 *     CCP3CON = 0x08, CCPR3H:L = 0x0300
 *     CCP4CON = 0x08, CCPR4H:L = 0x0400
 *     CCP5CON = 0x08, CCPR5H:L = 0x0500
 */

#include "pic16f193x.h"
#include "pic16f193x_sfr.h"
#include "peripherals/pic16f193x_gpio.h"
#include "peripherals/pic16f193x_ccp.h"
#include "core/pic16f193x_wdt_sleep.h"
#include "core/pic8_harness.h"

extern void pic16f193x_harness_halt(void);

static uint8_t check_instance(CCP_InstanceTypeDef inst, uint16_t compare,
                               uint16_t con_reg, uint16_t ccpr_h_reg, uint16_t ccpr_l_reg)
{
    CCP_HandleTypeDef h = CCP_HANDLE_DEFAULT;
    h.Instance = inst;
    h.Mode = CCP_MODE_COMPARE_SET;
    h.CompareValue = compare;
    HAL_CCP_Init(&h);

    uint8_t con = PIC8_REG8(con_reg);
    uint8_t hi = PIC8_REG8(ccpr_h_reg);
    uint8_t lo = PIC8_REG8(ccpr_l_reg);
    pic8_harness_log("inst=%d CON=0x%02X CCPR=0x%02X%02X\n", (int)inst, con, hi, lo);
    return (con == 0x08U) && (hi == (uint8_t)(compare >> 8)) && (lo == (uint8_t)(compare & 0xFFU));
}

int main(void)
{
    pic8_harness_init();

    uint8_t pass = 1U;
    pass &= check_instance(CCP_INSTANCE_3, 0x0300U, PIC_REG_CCP3CON, PIC_REG_CCPR3H, PIC_REG_CCPR3L);
    pass &= check_instance(CCP_INSTANCE_4, 0x0400U, PIC_REG_CCP4CON, PIC_REG_CCPR4H, PIC_REG_CCPR4L);
    pass &= check_instance(CCP_INSTANCE_5, 0x0500U, PIC_REG_CCP5CON, PIC_REG_CCPR5H, PIC_REG_CCPR5L);

    int rc = pic8_harness_report(pass);
    pic16f193x_harness_halt();
    return rc;
}
```
