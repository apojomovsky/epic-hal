# SR Latch for pic16f193x-hal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Status: **implemented and cleared the §4 gate.** Peripheral #10 in
`docs/pic16f193x-plan.md` §7's roadmap table. Register facts were
cross-checked against the installed DFP header before writing (Global
Constraints), not a substitute for the §4 gate actually running.

**Goal:** Land a `HAL_SRLATCH_*` driver for the hardware SR (set-reset)
latch (DS41364B §19.0) through the §4 gate, scoped to the
self-contained software-pulse-driven path (Non-goals covers what's
deferred).

**Architecture:** Two registers. `SRCON0` holds the master enable
(`SRLEN`), software pulse-set/pulse-reset triggers (`SRPS`/`SRPR`),
output-to-pin enables (`SRQEN`/`SRNQEN`), and a clock/pulse-width
select (`SRCLK`). `SRCON1` wires comparator C1/C2 and a clock signal
as additional hardware set/reset input sources, entirely deferred in
this phase since it depends on the (also pending) Comparator plan. No
existing analog in `pic16f87xa-hal`/`pic18fxx5x-hal`.

**Tech Stack:** C99, MPLAB XC8, gcc (host sim), CMake, GNU Make.

## Global Constraints

- C99, no compiler extensions in portable code.
- No em-dashes anywhere.
- Every register access is a compile-time-constant `PIC_REG_*` token.
- Handle-copy convention: copy by value, never store the pointer.
- **Standing warning**: every bit position here was re-derived from
  DS41364B and cross-checked against the installed DFP header's
  `_SRCON0_<FIELD>_POSN`/`_MASK` and `_SRCON1_<FIELD>_POSN`/`_MASK`
  macros
  (`/opt/microchip/xc8/v3.10/pic/packs/Microchip.PIC12-16F1xxx_DFP/xc8/pic/include/proc/pic16f1937.h`).
  Timer1 shipped with a wrong bit position (`PIC_T1CON_TMR1CS` at bit
  1, copied from `pic16f87xa`'s classic-PIC16 T1CON, real field is
  bits 7:6) from a transcription without this cross-check. Never trust
  a bit position from another family's driver or memory alone. No
  existing SR-latch driver anywhere in this codebase to copy from.

## Non-goals (not in this phase)

- Comparator-driven set/reset (`SRCON1`'s `SRRC1E`/`SRRC2E`/`SRSC1E`/
  `SRSC2E`): depends on the Comparator plan
  (`docs/superpowers/plans/2026-08-04-pic16f193x-comparator.md`)
  landing first.
- Clock-driven set/reset (`SRCON1`'s `SRRCKE`/`SRSCKE`): deferred for
  the same simplicity-first reason, added once comparator wiring is
  independently verified.
- Pin-driven set/reset (`SRCON1`'s `SRRPE`/`SRSPE`): also deferred in
  this first pass alongside the rest of `SRCON1`, to keep this plan's
  scope to `SRCON0` only.

```c
/* Bank 2. SRCON0/SRCON1, DS41364B Register 19-1/19-2. Verified
 * against the installed DFP header (pic16f1937.h) _SRCON0_*/
 * _SRCON1_* POSN/MASK macros; re-verify against DS41364B before
 * relying on them. */
#define PIC_REG_SRCON0          0x11AU
#define PIC_REG_SRCON1          0x11BU

#define PIC_SRCON0_SRPR         PIC8_BIT(0)  /* SRCON0<0>: pulse reset (self-clears). */
#define PIC_SRCON0_SRPS         PIC8_BIT(1)  /* SRCON0<1>: pulse set (self-clears). */
#define PIC_SRCON0_SRNQEN       PIC8_BIT(2)  /* SRCON0<2>: SRNQ-to-pin enable. */
#define PIC_SRCON0_SRQEN        PIC8_BIT(3)  /* SRCON0<3>: SRQ-to-pin enable. */
#define PIC_SRCON0_SRCLK_MASK   0x70U        /* SRCON0<6:4>: clock/pulse-width select. */
#define PIC_SRCON0_SRLEN        PIC8_BIT(7)  /* SRCON0<7>: latch enable. */

/* SRCON1: deferred this phase (Non-goals), defined now since they cost
 * nothing and the follow-up plan needs them. */
#define PIC_SRCON1_SRRC1E       PIC8_BIT(0)
#define PIC_SRCON1_SRRC2E       PIC8_BIT(1)
#define PIC_SRCON1_SRRCKE       PIC8_BIT(2)
#define PIC_SRCON1_SRRPE        PIC8_BIT(3)
#define PIC_SRCON1_SRSC1E       PIC8_BIT(4)
#define PIC_SRCON1_SRSC2E       PIC8_BIT(5)
#define PIC_SRCON1_SRSCKE       PIC8_BIT(6)
#define PIC_SRCON1_SRSPE        PIC8_BIT(7)
```

**Files:** Create `pic16f193x-hal/src/peripherals/pic16f193x_srlatch.c`.

**Interfaces:**

- [ ] **Step 1: Write the driver body**

```c
/**
 * @file    pic16f193x_srlatch.c
 * @brief   PIC16F193X SR latch driver implementation.
 */
#include "peripherals/pic16f193x_srlatch.h"
#include "pic16f193x_sfr.h"
#include "pic16f193x_platform.h"

HAL_StatusTypeDef HAL_SRLATCH_Init(const SRLATCH_HandleTypeDef *h)
{
    if (!h) return HAL_INVALID;

    uint8_t con0 = 0U;
    if (h->OutputQToPin) con0 |= PIC_SRCON0_SRQEN;
    if (h->OutputNotQToPin) con0 |= PIC_SRCON0_SRNQEN;
    PIC8_REG8(PIC_REG_SRCON0) = con0;   /* SRLEN left clear until Enable(). */

    return HAL_OK;
}

HAL_StatusTypeDef HAL_SRLATCH_DeInit(void)
{
    PIC8_REG8(PIC_REG_SRCON0) = 0x00U;
    return HAL_OK;
}

HAL_StatusTypeDef HAL_SRLATCH_Enable(void)
{
    PIC8_BIT_SET(PIC8_REG8(PIC_REG_SRCON0), PIC_SRCON0_SRLEN);
    return HAL_OK;
}

HAL_StatusTypeDef HAL_SRLATCH_Disable(void)
{
    PIC8_BIT_CLR(PIC8_REG8(PIC_REG_SRCON0), PIC_SRCON0_SRLEN);
    return HAL_OK;
}

HAL_StatusTypeDef HAL_SRLATCH_Set(void)
{
    PIC8_BIT_SET(PIC8_REG8(PIC_REG_SRCON0), PIC_SRCON0_SRPS);
    return HAL_OK;
}

HAL_StatusTypeDef HAL_SRLATCH_Reset(void)
{
    PIC8_BIT_SET(PIC8_REG8(PIC_REG_SRCON0), PIC_SRCON0_SRPR);
    return HAL_OK;
}

uint8_t HAL_SRLATCH_ReadQ(void)
{
    /* SRCON0 has no direct "current Q state" readback bit (SRPS/SRPR
     * are pulse triggers, not a status mirror); the only observable
     * state this phase is via SRQEN driving the physical SRQ pin,
     * which this HAL cannot read back without a GPIO handle on that
     * specific pin. Report via SRQEN as a proxy for "is Q routed
     * anywhere observable" is wrong; instead this returns whether the
     * output-enable is configured, and the example/gate verifies the
     * actual latch state via the mdb register readback of the GPIO
     * pin SRQ is routed to, not via this function. Document this
     * limitation instead of faking a readback the hardware doesn't
     * provide. */
    return (PIC8_REG8(PIC_REG_SRCON0) & PIC_SRCON0_SRQEN) ? 1U : 0U;
}
```

Confirm the exact platform macro names against a fresh read of
`pic16f193x_timer1.c` before finalizing. Also confirm during
implementation whether DS41364B documents any other way to read the
latch's logical Q state besides the physical pin (some PIC SR-latch
IP blocks expose it nowhere in registers at all, by design, since it's
meant to be read via the pin); if a real status bit exists, replace
`HAL_SRLATCH_ReadQ`'s body and the comment above with the real
readback instead of the documented limitation.

## Task 4: Host sim pulse-set/pulse-reset model

**Files:** Modify `pic16f193x-hal/src/sim/pic16f193x_sim.c`.

**Interfaces:** Consumes `PIC_REG_SRCON0` and its bit macros. Produces
`sim_step_srlatch` (match the existing `sim_step_*` naming

- [ ] **Step 1: Add the sim step**

```c
static uint8_t s_srlatch_q;  /* Simulated Q state, not a real SFR bit
                                (DS41364B provides no register
                                readback of Q on this device, see Task
                                3 Step 1's note); exposed to the
                                example via a GPIO pin the sim wires
                                SRQ to, per Task 6's example. */

static void sim_step_srlatch(void)
{
    uint8_t con0 = pic16f193x_sim_sfr[PIC_REG_SRCON0];
    if (!(con0 & PIC_SRCON0_SRLEN)) return;   /* Latch disabled: hold state. */

    if (con0 & PIC_SRCON0_SRPS) {
        s_srlatch_q = 1U;
        pic16f193x_sim_sfr[PIC_REG_SRCON0] = (uint8_t)(con0 & (uint8_t)~PIC_SRCON0_SRPS);  /* Pulse self-clears. */
    } else if (con0 & PIC_SRCON0_SRPR) {
        s_srlatch_q = 0U;
        pic16f193x_sim_sfr[PIC_REG_SRCON0] = (uint8_t)(con0 & (uint8_t)~PIC_SRCON0_SRPR);  /* Pulse self-clears. */
    }
}
```

Add a call to `sim_step_srlatch()` in the same per-step dispatch
function that already calls `sim_step_timer1()`, and expose
`s_srlatch_q` to the example either via a small accessor function

inspection hooks are named, check `pic16f193x_sim.c` for the existing
pattern used by GPIO/comparator-style injection/inspection points and

```c
/**
 * @file    example_srlatch.c
 * @brief   SR latch smoke test: enable, pulse-set, confirm Q went
 *          high; pulse-reset, confirm Q went low.
 *
 * @details
 *   Expected register image (host sim, after enable + set pulse):
 *     SRCON0 = 0x80   (SRLEN=1, SRPS self-cleared back to 0 by the
 *                      sim step, SRQEN/SRNQEN=0 in this test)
 *   The simulated Q state (not a real SFR bit, see the driver's
 *   HAL_SRLATCH_ReadQ note) is asserted via the sim's inspection
 *   accessor, not via a register readback.
 */

#include "pic16f193x.h"
#include "pic16f193x_sfr.h"
#include "peripherals/pic16f193x_gpio.h"
#include "peripherals/pic16f193x_srlatch.h"
#include "core/pic16f193x_wdt_sleep.h"
#include "core/pic8_harness.h"

extern void pic16f193x_harness_halt(void);
/* Sim-only inspection hook, see pic16f193x_sim.c Task 4; not present
 * in the target build, guard appropriately if this header is shared
 * across host/target builds (check how other sim-only inspection
 * calls are guarded elsewhere in this codebase, e.g. via a
 * host-vs-target file split rather than #ifdef, per the root
 * CLAUDE.md's "applications never #ifdef between them" rule, so this
 * accessor should live in a host-only file, not be called directly
 * from a dual-build example; on target, use the SRQ pin's GPIO
 * readback instead, wired via HandleQToPin=1 at Init time). */

int main(void)
{
    pic8_harness_init();

    SRLATCH_HandleTypeDef sr = SRLATCH_HANDLE_DEFAULT;
    HAL_SRLATCH_Init(&sr);
    HAL_SRLATCH_Enable();
    HAL_SRLATCH_Set();

    uint8_t con0 = PIC8_REG8(PIC_REG_SRCON0);
    pic8_harness_log("SRCON0=0x%02X\n", con0);
    int rc = pic8_harness_report(con0 == 0x80U);
    pic16f193x_harness_halt();
    return rc;
}
```

This example intentionally verifies only the register-level
enable/pulse-and-self-clear behavior (provable identically on host sim
and real target via `mdb`), not the simulated Q state, since Q has no
real-hardware register readback (Task 3's documented limitation) and a
dual-build example must assert on something both builds can see the
same way. If a real per-pin GPIO readback of SRQ is wired in during
implementation (`HandleQToPin=1` + read the corresponding GPIO input
register), extend this example to assert on that too, it would be a
stronger test; write it if the wiring is straightforward, don't force
it if it adds real complexity disproportionate to this peripheral's
scope.
