# Plan: CI target-job speed

Date: 2026-08-11. Status: in progress.

The host job finishes in ~1 min; the target job is the long pole at
~23 min. This plan breaks down where the time goes, ranks the options,
and lands the recommended ones. Measured from the PR #22 target run
(2026-08-10, run 31418702101, 23m14s):

| Step | Wall | Share | What it is |
|---|---|---|---|
| Image pull | 1m02s | 4% | 5.7 GB GHCR pull, unavoidable per runner |
| Device-data audits | 1m37s | 7% | sfr-map (3s) + config-key (149 links, ~90s, sequential docker runs) + statics (instant) |
| Hex-rebuild identity | 7m04s | 30% | every matrix hex built twice: 224 sequential xc8 builds |
| Emit | 11s | 1% | manifest resolution + build.sh emission + bundle tarballs |
| Real XC8 builds | 3m04s | 13% | 112 sequential xc8 builds |
| MPLAB SIM (mdb) | 9m43s | 42% | 32 sequential gates, wall-clock wait_ms (5s each, two at 60s) |
| Bundle build | 33s | 2% | 3 families x (demo project + module app) |

Three loops (builds, gates, hex-identity) are sequential inside one
job on a 2-core runner and account for 85% of the wall. The machine
has idle capacity the whole time: each xc8 build and each mdb session
is single-threaded.

## Options

### A. Shard the target job by family (recommended, the big win)

Split `target` into three concurrent jobs: `target-87xa`,
`target-18fxx5x`, `target-193x`. GitHub runs jobs in parallel on
separate runners, so the PR wait becomes the largest family's time
instead of the sum. The 87XA family carries ~50 of the 112 builds and
~20 of the 32 gates; the PIC18 and 193X jobs are much smaller. Each
job: pulls the image (parallel, wall still ~1m), runs its family's
audits (sfr-map, config-key, statics, hex-identity scoped to its
legs), emits + builds its matrix legs, runs its sim gates, and builds
its bundle. The emit step currently resolves the whole manifest and
writes one matrix.txt; the shard emits a per-family matrix.txt and a
per-family sim list.

Expected: 23m -> ~11-13m (the 87XA job's gates dominate).

### B. Parallelize inside the family jobs (recommended, compounds with A)

Each build loop and gate loop is a `for` loop inside the container.
Convert to `xargs -P2` (the runner has 2 cores): the 112 builds at
~1.5s each -> ~1.5-2m wall; the gates' wall-clock waits stop stacking
(~30 x 5s + 2 x 60s sequential -> ~2.5-3m wall at -P2). Prerequisite:
sim-mdb-run.sh's temp files (/tmp/<family>-uart.txt, /tmp/<family>
-mdb.txt) collide between concurrent same-family runs; suffix them
with the PID. The summary appends must stay atomic (short lines).

Expected with A: the 87XA job ~6-8m, total wall ~7-9m.

### C. Reduce the hex-identity audit set

The audit builds the full matrix twice (224 builds). The task-5c
contract is "the gate .hex files": the 32 gate hexes doubled (64
builds) would cut 7m04s to ~2m at the cost of coverage (the matrix
catches drift anywhere, not just in gated modules). Keep the full
matrix; scoping per family (A) already splits the 224 builds across
the three jobs.

### D. Parallelize the config-key audit

151 sequential docker runs (~90s). Thread it (4 workers) -> ~30s.
Small win, easy.

### E. Image pull (1m02s)

Accepted: it is a fresh runner pulling a 5.7 GB image. A
`docker/build-push-action` cache would need a cache backend and does
not obviously beat GHCR here; revisit only if the job gets close to
the pull's size.

## Decision

Land A + B + D: shard by family, parallelize the BUILD loops with
xargs -P2 (module-granular: XC8 writes its startup object next to the
-o hex at build/<module>/, so concurrent legs of one module corrupt
each other), thread the config-key audit. The mdb GATES stay
sequential in CI: at PARALLEL=2 on the 2-core runner, concurrent mdb
sessions halved the effective sim speed and two marginal 5s-budget
gates (epic-bus, epic-combo-encoder-tick) missed their markers
(2026-08-11, PR #25 first sharded run); a contention-flake class
would undo the task-10 hardening. The PARALLEL machinery stays for
local flake hunts. Keep the full-matrix hex-identity check (scoped
per family). Target: PR target checks in ~11-12 min (the 87XA job's
sequential gates dominate).

## Verification

- Local: the per-family loops + a parallel gate pair (temp-file
  uniqueness proof), the config-key audit threaded run.
- CI: the sharded jobs green on the PR; step timings show the wall
  drop.

## Follow-up (recorded, not done)

- The toolchain image slimmed 2026-08-11: 5.7 GB -> 3.98 GB (the
  MPLAB X GUI/MCC/thirdparty platform chunks mdb never loads, the
  GTK/X11 apt libs, the XC8 AVR support, both products' docs). The
  prune set was trial-and-error-verified against the gate suite; the
  image pull drops accordingly.
- The two 60s gates (swuart, 193X firmware) are the next wait_ms
  candidates once the parallelization lands.
